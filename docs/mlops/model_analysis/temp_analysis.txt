Alternatives to increasing the batch_size:
- if wanted to forgo the fine grained ranking that comes from list-wise training from in-batch softmax,
  I can switch to point-wise loss from a sigmoid loss.
  Sigmoid loss does not evaluate the positive against a 
  pool of negatives so no large variability from denominator.
  - the resulting "scores" would be absolute probabilities.
    - this would enable batch queries to get meaningful comparisons
      for some factor of num_candidates (resulting in that factor 
      of top_k results).
    - what is lost is some amount of precision is presenting a
      an ordered list of recommendations
- the pointwise train_steps and eval_steps are coded as pointwise_training.py
   while waiting for the list-wise training with larger batch_size to finish.


Sigmoid Function (Logistic Function)
   sigma(z) = 1 / (1 + exp(-z))
     Where:
        z is the raw model logit score

Sigmoid Loss (Binary Cross-Entropy for a single sample)
    L(y, p) = - [ y * log(p) + (1 - y) * log(1 - p) ]
      Where:
         y is the true binary label (0 or 1)
         p is the predicted probability, where p = sigma(z)

Combined Expanded Form (Substituting the Sigmoid into the Loss)
    L(y, z) = - [ y * log(1 / (1 + exp(-z))) + (1 - y) * log(1 - (1 / (1 + exp(-z)))) ]
